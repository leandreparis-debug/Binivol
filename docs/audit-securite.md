# Audit de sécurité (étape 15)

Revue faite la nuit du 05 au 06/11/2026 sur la V1 (démo Vercel + Supabase, données fictives).

## Ce qui a été vérifié et corrigé

| Point                                | État                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **En-têtes HTTP** (`next.config.ts`) | Ajoutés : `Content-Security-Policy` (tout en `'self'`, `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self' https://accounts.google.com`), `Strict-Transport-Security` (2 ans, sous-domaines). Déjà là : `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Permissions-Policy` (caméra, micro, géolocalisation, paiement… refusés), `Referrer-Policy: no-referrer` + `no-store` + `noindex` sur `/dossier`. |
| **Limitation de débit**              | Nouvelle table `rate_limits` (fenêtre fixe, clé = SHA-256 du seau et du client, jamais l'adresse IP) : ouverture d'un lien de dossier (20 / 15 min), écritures du dossier (300 / 15 min), tentatives de connexion (30 / 15 min par client ; depuis ADR-070, en plus 5 échecs / 15 min par identifiant). Les codes de signature avaient déjà leurs limites (5 envois par heure, 5 essais par code). Portable : marche à l'identique sur un VPS.          |
| **Actions serveur**                  | Toutes passent par `defineAction` ou la liste fermée `definePublicAction` (test d'architecture existant).                                                                                                                                                                                                                                                                                                                                               |
| **Gardes de page**                   | Nouveau test d'architecture : chaque page de l'espace connecté appelle `requirePageAccess`, `authorizePage`, `requireActor` ou `requireDossierPage` (seule exception justifiée : la vitrine du design system).                                                                                                                                                                                                                                          |
| **Données sensibles**                | Jamais dans le rendu initial (règle de l'étape 5, tests existants) ; lues par `sensitive.ts` (journalisé), le dossier par `store.ts` (test d'architecture). Les nouveaux modules (alertes, purge, export RGPD) passent par eux.                                                                                                                                                                                                                         |
| **Fichiers**                         | Servis seulement par des routes qui vérifient les droits et journalisent ; toujours en pièce jointe, `no-store`, `nosniff`, `Content-Disposition` encodé ; jamais d'URL publique ni présignée. Export RGPD réservé à TOPAZE (`person.gdprExport`).                                                                                                                                                                                                      |
| **IDOR**                             | Les routes `/api/documents/[id]`, `/api/exports/[kind]`, `/api/rgpd/[ref]` résolvent l'objet puis appellent `can()` sur la personne ; un identifiant d'un autre périmètre donne 403/404 (tests base des étapes 5, 13, 14).                                                                                                                                                                                                                              |
| **Injection CSV**                    | Toute cellule qui commence par `=`, `+`, `-`, `@`, tabulation ou retour chariot est préfixée d'une apostrophe (`src/lib/csv.ts`, testé).                                                                                                                                                                                                                                                                                                                |
| **Tâche planifiée**                  | `CRON_SECRET` comparé en temps constant ; sans secret (ou trop court), refus total.                                                                                                                                                                                                                                                                                                                                                                     |
| **Dépendances** (`pnpm audit`)       | 2 hautes et 3 modérées sur `postcss` (dépendance de Next, traitement de **nos** feuilles de style au build) et `uuid` (via `exceljs`) : corrigées par des `pnpm.overrides` vers les versions patchées. Reste 1 modérée : `minimatch` via `eslint-config-next` (outil de développement, jamais en production).                                                                                                                                           |
| **Secrets**                          | Recherche des motifs de clés (AWS, Stripe, GitHub, Slack, clés privées) dans le dépôt : aucun. `.env.example` complet et sans valeur (dont `CRON_SECRET`, `BACKUP_ENCRYPTION_KEY`).                                                                                                                                                                                                                                                                     |

## Limites connues, à traiter plus tard

- **CSP sans nonce** : `script-src` garde `'unsafe-inline'` (scripts d'amorçage de Next.js). Un
  nonce par requête demanderait un rendu dynamique de toutes les pages ; à faire avec le passage
  au VPS. Les autres directives restent strictes (aucune origine tierce).
- La limitation de débit compte par adresse IP déclarée par la plateforme (`x-forwarded-for`) :
  fiable derrière Vercel ou un proxy maîtrisé, à reconfigurer sur le VPS (proxy de confiance).
- Les connexions de démonstration ne sont pas limitées (elles n'existent jamais en production).
